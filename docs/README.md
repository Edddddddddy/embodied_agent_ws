# 文档中心

本目录是项目文档的统一入口。README 负责快速启动，本文负责导航；设计细节、测试方法和实测结论分别维护，避免同一数据在多个文件中失去同步。

## 推荐阅读顺序

1. [`../README.md`](../README.md)：项目定位、安装、启动和最短演示路径。
2. [`KNOWLEDGE_NOTES.md`](KNOWLEDGE_NOTES.md)：从 ROS 2、流式语音到硬件控制的知识点笔记。
3. [`PROJECT_NOTES.md`](PROJECT_NOTES.md)：关键代码在哪里、模块如何协作、配置在哪里修改。
4. [`TESTING_GUIDE.md`](TESTING_GUIDE.md)：单元测试清单、分层验收命令和新增测试规范。
5. [`COMPLETION_REPORT.md`](COMPLETION_REPORT.md)：当前完成度、实测数据、未完成项和成果表述边界。
6. [`../training/README.md`](../training/README.md)：数据集与 LLaMA-Factory LoRA 训练占位说明。

## 文档职责

| 文档 | 回答的问题 | 更新时机 |
|---|---|---|
| 根目录 README | 如何安装、启动和演示？ | 启动方式或默认配置改变时 |
| 知识点笔记 | 这里用了哪些技术，为什么这样设计？ | 架构或核心算法改变时 |
| 项目设计笔记 | 关键代码和参数具体在哪里？ | 文件、话题、配置或协议改变时 |
| 测试指南 | 功能由哪个测试覆盖，如何复现？ | 新增功能、测试或验收脚本时 |
| 完成度报告 | 哪些指标真实达标，哪些仍缺证据？ | 完整验收或目标硬件改变时 |

## 三条主要运行链路

```text
在线：音频前端 -> 云 ASR -> 云 LLM -> 云 TTS -> 动作安全 -> 硬件控制
离线：音频前端 -> ZipFormer -> llama.cpp -> Sherpa-TTS -> 动作安全 -> 硬件控制
测试：合成/文字输入 -> ROS 话题 -> Agent -> C++ Guard -> mock/PTY 传输 -> ACK
```

项目中的性能数字必须带上运行环境、冷启动或预热状态、样本数及统计口径。单次通过只能证明链路可运行，不能代替 P50/P95 或独立准确率评测。
