## 1. 控制器的输入和输出

`SimulationController` 是纯 C++ 控制逻辑，不直接依赖 ROS：

```text
输入：配置、动作命令、LaserScan、当前时间
状态：mode、目标速度、当前速度、截止时间、雷达摘要、PID
输出：VelocityCommand + 安全/诊断状态
```

ROS seam 在 `SimulationControlNode`：订阅 LaserScan、按 20 Hz 调用 `step()`、把输出转成 `geometry_msgs/Twist` 发布到 `/cmd_vel`。

纯逻辑与 ROS 分离后，控制算法可以用合成 scan 和时间戳做确定性单测，不需要启动 Gazebo。

## 2. 差速底盘速度语义

项目只使用：

- `linear.x`：车体 x 轴前后速度，m/s；
- `angular.z`：绕 z 轴角速度，rad/s。

差速机器人不能横移，所以 `linear.y` 始终为 0。move 设置 `(linear_x, 0)`，turn 设置 `(0, angular_z)`。

`duration_s` 不传给底盘驱动，而由上层计时。底盘收到的是持续更新的瞬时速度，直到控制节点发布零速度。

## 3. LaserScan 扇区提取

`update_scan()` 遍历 ranges，先过滤：

```text
非有限值
range < range_min
range > range_max
```

然后根据：

```text
angle = angle_min + index * angle_increment
```

把角度归一化到 `[-pi, pi]`，计算三个扇区最近距离：

- front：中心 0°，半宽 20°；
- left：中心 +90°，半宽 25°；
- right：中心 -90°，半宽 25°。

为什么取最小值：安全决策关心扇区内最近障碍。缺点是单点噪声会支配结果，生产实现可使用分位数、连续点数量或滤波降低孤立噪点影响。

每次 scan 还记录 `last_scan_s_`。控制器不是只看“最近一次距离”，还要判断这个距离是否过期。

## 4. 手动动作模式

`set_manual_command()`：

1. 强制切回 manual；
2. clamp 线速度和角速度；
3. 计算 `manual_until_s = now + clamp(duration, 0, 10)`；
4. 清除 force stop；
5. 重置 PID。

`step()` 中只有 `now <= manual_until_s` 才使用目标速度，过期后 target 默认为零。速度不会瞬间从当前值降为零，而是经过 acceleration ramp；Action server 在 duration 到达时会额外调用 `stop()` 并强制发布零，保证任务终态明确。

## 5. scan stale 的安全策略

```text
scan_stale = now - last_scan > 0.50s
```

对任何向前 target，scan stale 都会把 `linear_x` 归零并设置 `safety_stopped=true`。这包括 manual forward。倒车和原地转向当前不因 stale 被同样阻断，因为安全检查只针对 `target.linear_x > 0`。

自主模式遇到 stale 时本来就不产生目标速度。`reason=scan_timeout` 进入 diagnostics 和 Action blocked detail。

这是 fail-safe 设计：没有新传感器数据不等于前方安全。

## 6. 前方急停与普通避障阈值

默认：

```text
emergency_distance = 0.22 m
obstacle_distance  = 0.50 m
```

配置校验要求 obstacle distance 大于 emergency distance。

- emergency threshold 是所有前进模式的硬安全截断；
- obstacle threshold 用于 obstacle-avoidance/wall-following 的行为决策。

即使自主算法认为应该继续前进，只要 front 小于 0.22 m，最后的安全层仍将线速度归零。

### 6.1 `/robot/emergency_stop` 的当前边界

ROS 回调 `SimulationControlNode::on_emergency_stop()` 当前只执行 `executor_->stop()`、发布 mode 和 ACK。它没有调用 `SimulationController::set_emergency_stop(true)`，也没有立刻结束 `active_goal_`。因此：

- 底盘速度会归零并切回 manual；
- 当前 duration Action 可能继续保持 active，直到后续 duration/cancel/preempt 终态；
- 后续新命令仍可以再次运动；
- 它不是需要人工复位的 latched hardware E-stop。

`SimulationController::set_emergency_stop()` 本身实现了 latch 状态并有单测，但尚未通过 `RobotExecutor` 接口接到这个 ROS Topic。生产化应让急停同时停车、终止活动 goal、锁定新运动并要求显式 reset；实体机器人还应有独立硬件急停回路。

## 7. 简单避障模式

逻辑：

```text
front < obstacle_distance:
    linear = 0
    angular = left >= right ? +turn_speed : -turn_speed
else:
    linear = autonomous_linear_speed
```

机器人朝更空旷一侧旋转。它没有局部地图、轨迹采样、死锁恢复或目标方向，因此只是反应式避障演示，不是 Nav2 local planner。

对称走廊中 left/right 近似相等时固定偏左，可能产生振荡或局部循环。

## 8. 沿墙 PID

沿右墙时定义：

```text
error = target_distance - right_distance
```

默认 target 为 0.40 m。墙太近时 right=0.20，error 为正，angular_z 为正，即左转远离右墙。

离散 PID：

```text
integral = clamp(integral + error * dt, -0.5, 0.5)
derivative = (error - previous_error) / dt
angular = clamp(Kp*error + Ki*integral + Kd*derivative)
```

默认 `Kp=1.8, Ki=0, Kd=0.15`，本质是 PD。积分状态仍实现并限幅，便于以后启用 Ki，避免 windup。

特殊分支：

- 前方有墙：左转并 reset PID；
- 右侧无有效墙：低速向前并向右搜索；
- 否则正常跟踪。

## 9. 加速度斜坡

若没有 force stop 或 safety stop，current velocity 通过：

```text
approach(current, target, acceleration * dt)
```

逐步接近 target。20 Hz、线加速度 0.5 m/s² 时，每 tick 最多改变约：

```text
0.5 * 0.05 = 0.025 m/s
```

这减少速度突变。`dt` 被 clamp 到 `[0.001, 0.20]`，避免 timer 抖动或长暂停导致一步跳变过大。

安全 stop 不走斜坡，立即赋 target 零。舒适性不能压过安全性。

## 10. ROS 控制周期

`control_tick()`：

1. `executor_->step(now)`；
2. 保存 diagnostics snapshot；
3. `update_active_action()`，可能结束并 stop；
4. 构造 Twist；
5. 如果本 tick action 结束，强制 Twist 为零；
6. publish `/cmd_vel`；
7. publish JSON simulation state。

控制器输出、Action 状态和 Topic 发布在同一周期协调，减少“任务已成功但仍发旧速度”的窗口。

## 11. 如何证明机器人真的执行

证据强度从弱到强：

1. action candidate：模型产生了意图；
2. Guard accepted：静态校验通过；
3. Action feedback/ACK：执行节点开始处理；
4. `/cmd_vel`：控制器发布了速度；
5. `/odom`：仿真/硬件里程计观察到位姿变化；
6. 外部定位或物理测量：独立确认真实机器人移动。

Gazebo 测试订阅 odom，比较开始/结束位置。Action success 单独只能证明持续时间状态机完成，不保证轮子没有打滑或 bridge 未断。

## 12. 测试证据

`test_simulation_controller.cpp` 覆盖：

- 手动命令过期和速度限制；
- 15 cm 前障碍立即阻断；
- 朝更空的一侧转；
- 自主模式 scan stale 停车；
- 右墙过近向左修正；
- emergency stop 后不自动恢复；
- stop 退出自主模式；
- manual forward 无 scan 也停车。

其中 emergency latch 单测直接调用 `SimulationController::set_emergency_stop()`；它不能证明当前 ROS emergency Topic 已接通 latch。

## 13. 面试回答模板

**问题：项目如何做避障？**

LaserScan 回调先过滤无效 range，再从前方 ±20°、左右 ±25° 扇区提取最近距离，并记录 scan 时间。20 Hz 控制循环根据 mode 计算目标速度：简单避障在前方 0.5 米内停止前进并朝更空一侧旋转，沿墙模式用右侧距离误差做 PD 控制。所有模式之后还有统一安全层，scan 超过 0.5 秒未更新或前方小于 0.22 米时，向前速度立即归零并把 Action 终态设为 BLOCKED。正常速度变化经过加速度斜坡，安全停车则绕过斜坡。这个实现是反应式局部控制，不包含地图、定位和全局路径规划，完整导航由 Nav2 负责。
