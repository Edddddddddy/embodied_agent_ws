# 项目源码深度讲解

这套材料面向“会读 Python/C++，但刚开始系统学习 ROS 2”的读者。目标不是背 API，而是能回答四类问题：

1. 一条语音命令经过了哪些进程、线程、Topic、Action 和状态机？
2. 每层为什么这样设计，替代方案有什么代价？
3. 发生丢帧、超时、障碍、取消或硬件故障时，代码会走哪条分支？
4. 哪些能力已由代码和测试证明，哪些只是未来可以扩展？

## 事实边界

- 主项目完成的是语音驱动的 `move / turn / stop` 等动作闭环，不是完整的 Nav2 全局导航。
- “降噪”部分实际实现为 NLMS 声学回声消除、能量 VAD 和静音断句；没有频谱降噪、麦克风阵列波束形成或 WebRTC NS。
- Gazebo ACK 证明控制节点接收并处理了命令；结合 `/odom` 位移才构成物理执行证据。
- UART/SPI 当前 ACK 主要表示主机侧帧已发送，不等价于下位机完成动作。
- LoRA 只有数据和配置，尚未训练；fallback 指令成绩不能当作模型准确率。
