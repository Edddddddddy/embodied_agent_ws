# 16 学习记录与自测

## 1. 如何判断“看懂了”

看文档时觉得顺畅只是熟悉感。掌握需要在不看答案时完成检索、推演和解释。本文件用于记录每轮学习，不修改业务代码。

每章使用四级状态：

```text
0 未读
1 能复述结论
2 能从入口追到关键函数
3 能推演异常分支并回答设计取舍
```

## 3. 每章学习循环

### 第一次：建模

1. 只读“本章问题”和图。
2. 自己预测调用链。
3. 打开源码验证预测。
4. 记录至少一个预测错误。

### 第二次：追代码

1. 从入口函数开始，不使用全文总结。
2. 写出每个函数的输入、状态修改、输出和副作用。
3. 找到一个正常分支和两个异常分支。
4. 找到对应测试。

### 第三次：闭卷检索

1. 不看文档画时序图或状态图。
2. 回答章节末自测。
3. 用 `rg` 在 60 秒内找到关键实现。
4. 讲一遍“为什么不选替代方案”。

### 第四次：面试表达

1. 30 秒讲结论。
2. 2 分钟讲代码和设计。
3. 接受一个反例追问。
4. 主动说明事实边界。

## 5. 必做源码定位挑战

在不看章节答案时，用 `rg` 找到：

```bash
# 谁发布 action candidate
rg -n "action_candidate.*publish|_action_pub.publish" src

# 哪一行限制 move 速度和时长
rg -n "linear_x.*clamp|duration_s.*clamp" src/embodied_agent_cpp

# Action blocked 从哪里产生
rg -n "kBlocked|STATUS_BLOCKED|safety_stopped" src/embodied_simulation

# 生命周期 deactivate 如何停车
rg -n "on_deactivate|publish_zero_velocity|executor_->stop" src/embodied_simulation

# plugin 描述与导出
rg -n "PLUGINLIB_EXPORT|pluginlib_export_plugin" src/embodied_simulation

# offline buffer 的 close/abort
rg -n "message_buffer\.(close|abort)|audio_buffer\.(close|abort)" src
```

目标不是背行号，而是能从领域词快速导航到实现。

## 6. 手算练习

### 6.1 音频

- 16 kHz、20 ms：样本数 `320`，PCM16 字节 `640`。
- 连续 400 ms 静音：`20` 帧。
- 24 kHz reference 2400 样本重采样到 16 kHz：约 `1600` 样本。

### 6.2 控制

- 20 Hz tick：周期约 `0.05 s`。
- 线加速度 0.5 m/s²：每 tick 最大变化 `0.025 m/s`。
- 右墙 0.2 m、目标 0.4 m、Kp 1.8、Kd=0：P 输出 `+0.36 rad/s`。

### 6.3 协议

- 0.2 m/s -> int16 `200` -> little-endian `C8 00`。
- 1.0 s -> uint16 `1000` -> little-endian `E8 03`。
- 完整 frame 还需 header/version/opcode/length/sequence/CRC。

推荐场景：

- 未说唤醒词；
- LLM 输出坏 JSON；
- move 多一个参数；
- Guard inactive；
- Action server 不可用；

- emergency Topic 停车但 Action 未立即结束；
- 新 goal 抢占旧 goal；
- plugin 名错误；
- UART partial write；
- Nav2 goal canceled。

## 8. 模拟面试评分

每题 10 分：

| 维度 | 分值 |
|---|---:|
| 先给准确结论 | 2 |
| 能说出真实调用链 | 2 |
| 能指出关键状态/线程 | 2 |
| 能解释取舍 | 2 |
| 有测试证据和事实边界 | 2 |

低于 8 分不要重背答案，回到对应源码做一次“入口 -> 状态 -> 终态”追踪。

- 任意抽取 5 道源码题，平均至少 8 分。
